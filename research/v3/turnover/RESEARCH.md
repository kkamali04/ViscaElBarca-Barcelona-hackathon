# Turnover-aware possession decoding: research and proposed contract

Research cutoff and retrieval: **2026-11-15**. Status: **research complete; implementation and empirical improvement untested**. Owner: turnover research specialist. This document is input to the PRD, not permission to promote a model.

## Prioritized decision

1. **Build a small, typed boundary head that reduces selected transition penalties in the existing exact three-state decoder.** Keep the accepted emitter/features frozen for the first ablation. This is a context-dependent transition model, distinct from adding another smoothing window. Export numeric parameters and retain NumPy-only CPU inference. Its value is a hypothesis requiring fresh whole-match evidence.
2. **Use ruptures/PELT as an optional development diagnostic or independent generic change-point baseline**, not as an additional mandatory production dependency or a possession oracle. If learning a boundary head is infeasible, retain the accepted constant-cost decoder; do not promote a proximity-sign rule merely because its transitions look plausible.
3. **Defer explicit-duration HSMM and full PathCRF/ASRF deployment.** HSMM is a meaningful alternative if duration errors dominate after the first experiment. PathCRF offers unusually relevant 2026 evidence for dynamic transitions, but its published task, input representation, episode selection and GPU benchmarks differ materially from this project. ASRF supports separating boundary evidence from frame evidence, rather than proving a soccer transfer.

## Local architecture and genuine increment

Read-only code audit: `possession_model/{schema,features,evidence,trees,decoder,pipeline}.py`, `experiments/noise_v2/features.py`, `tools/run_candidate.py`, public evaluation source and `validation/README.md`. No restricted tracking, tags, video, GT, actual CSV or timeline was opened or sent to tools.

The existing FeatureSet stores anonymous per-team nearest ball distance, tracked counts and set-motion proxy, ball position/observation/speed and periods. It does **not** retain identified player trajectories, ball height or per-player speed. Existing evidence already includes 0.6/3-second proximity summaries, 1/4-second observation/motion context, time since observation, pitch-boundary evidence and teleport guards. Accepted noise-v2 additionally estimates ball motion with a gap-safe centred 1.2-second local-linear slope. These are not new proposals.

`pipeline.predict` currently constructs a constant 3x3 off-diagonal cost from `transition_seconds * fps`. `decode_scores` maximizes summed evidence minus switching costs with deterministic tie rules, independent positive-period runs, forbidden-state handling and O(9N) work; it is already exact Viterbi-style decoding. Rebranding it as an HMM, adding constant asymmetric costs or another proximity mean does not establish change awareness. The proposed increment is **observation-dependent edge costs at the boundary between t-1 and t**, estimated separately from per-frame class evidence.

Scores are explicitly uncalibrated evidence. `transition_seconds` is a score-scale convention, not a minimum possession duration or an estimated probability. Existing exports constrain TreeModel to three numeric classes; any boundary export must declare different class semantics explicitly rather than silently relabel the accepted H/A/D model.

## Proposed small interface and data contract

This is an implementation recommendation, **not implemented API**:

```python
build_boundary_features(features: FeatureSet) -> (float32[N,F], names, valid: bool[N,2])
boundary_model.scores(matrix, names) -> float32[N,3]  # NONE, TEAM_CHANGE, LIVE_DEAD
boundary_evidence(logits, valid, calibration) -> float32[N,2]  # q_team, q_live_dead
decode_change_aware(scores, period_id, base_costs, boundary_evidence,
                    strength) -> int8[N]  # H/A/D internally, -1 outside periods
```

Boundary t means the edge **from t-1 to t**. The first row of each positive period run has no incoming edge. The head models directionless typed boundaries: H<->A versus H/A<->D. Distinct D-entry/exit heads are a later ablation, not part of the first small model. No mandatory D between H and A; a turnover is not dead play.

For i!=j define `C_t(i,j)=C_base(i,j)*(1-alpha*q_t(type(i,j)))`; diagonal remains0, with0<=alpha<1. Preserve any +infinity forbidden edges explicitly rather than multiplying infinity by0. This first version only lowers switching costs near supported boundaries; it never rewards switching with negative costs. At alpha=0, it must reproduce the old objective, constraints and ties exactly. Invalid/missing boundary evidence sets its modulation to0, giving the baseline cost. It must **not** interpret a missing ball as a positive dead-play boundary or as known absence of a turnover. Reject malformed NaN/range/shape parameters; documented invalid observation masks are the valid fallback mechanism.

Use stable softmax and a frozen temperature only if selection supports it; outputs are boundary support scores until calibration is measured. Three-class balancing changes class priors and can inflate apparent probabilities. Treat temperature/alpha as controlled selection parameters, not confidence claims. No emitter posteriors from a head fitted on the same rows are needed for the initial boundary features.

Available feature families: period-local differences of team distance margin; separate **before** and **after** proximity summaries at0.2/0.6seconds; whether both sides have finite geometry; ball observation transitions and gap lengths; before/after reliable ball speed and anonymous team set-motion; pitch-boundary distance/outside evidence and tracked counts. The new information is temporal direction across an edge, not merely another centred mean. Windows must neither cross periods nor interpolate gaps. Reliability must gate geometry-derived channels. A later ball direction-change feature can use continuous reliable ball_xy only; the current1.2s slope can blur touches, so new acceleration/angle features require their own robustness ablation. No raw slot-to-slot velocity or inferred persistent identity.

Targets derive **only from lawful training labels**: within contiguous known labels in the same period, NONE if unchanged, TEAM_CHANGE for H<->A, LIVE_DEAD for H/A<->D. Unknown truth/period edges are excluded. Start with exact boundaries; preregister any tolerance dilation, loss weighting, negative sampling and conflict handling before selection. If annotation jitter motivates positive neighborhoods, that is another declared target definition, not an after-test repair. Do not use synchronized-event labels, true in-play episode cuts or future labels at inference. Centred **observations** are allowed offline; labels never enter feature or reliability construction.

Model reuse: use current small boosted-tree training/export pattern with a distinct boundary schema and explicit class_names, feature order, fps/window version, calibration, training manifest and hashes. Current three-class numerical inference can be factored/reused only with an explicit adapter; preserve accepted H/A/D export semantics and files. Limit the first experiment to a small tree count/leaf budget declared in the PRD; below1MB extra numeric model is a target, not a result.

Keep O(9N) decoder work and O(3N) uint8 backpointers. Store two float32 boundary channels (8N bytes, about1.6MB at200k frames) rather than an Nx3x3 time-varying matrix. Compute per-edge costs on demand. Boundary feature buffers add4NF bytes unless streamed/released; measure whole-process peak RSS, including validation temporaries and model inference. No CPU latency estimate is yet established.

## Experiments and independent acceptance proposal

The PRD must freeze legal data, label semantics, whole-match train/selection/fresh-test roles, seeds, attempt budget, code/export hashes and quality/resource gates **before new training or fresh test access**. Closed v1/v2 scored holdouts and challenge GT/public windows remain closed. Any lack of genuinely unused matches is a blocking scientific limitation to promotion, not permission to reuse old test labels.

Use a factorial study so wider training does not get credited to the decoder:

| Arm | Emitter/training data | Decoder |
|---|---|---|
| A | accepted frozen emitter | accepted constant costs |
| B | same accepted emitter | typed boundary modulation |
| C | broader robustness emitter | same constant decoder |
| D | same broader emitter | same boundary modulation design |

Train boundary heads only on each arm's allowed training matches. Choose all parameters only on selection matches, then freeze one candidate for fresh test. Additional controlled selection-only axes: type-agnostic versus typed boundary; proximity-before/after versus all available feature families; reliable gating on/off; alpha=0; exact versus declared tolerant target; optional bounded-duration alternative if time permits. Cap this matrix in advance to avoid turning freshness into unlimited search.

Hypotheses: H1 boundary modulation increases typed transition F1 at12/25 frames and official mean spell F1 while holding frame macro-F1/alive-dead F1 within declared limits; H2 reliability gating limits false transitions after teleports, dropouts and reacquisition; H3 the B-A improvement survives with emitter fixed, while D-C tests complementarity with broad training; H4 brief correct spells remain recoverable and long same-team passes do not create false turnovers. All may fail; no paper benchmark implies they pass.

Recommended promotion gates for PRD review: preregister a meaningful minimum selection improvement and a paired whole-match fresh-test criterion, with explicit clean/occlusion/player-corruption non-regression bounds. Do not derive those thresholds after examining test scores, and do not compute frame-independent confidence intervals. Report every match/condition plus paired match/segment bootstrap limits where enough independent units exist. Use the actual organizer implementation: headline mean spellF1 across IoUs0.3..0.7; typed transition F1 at12/25frames; macroF1 and alive/dead F1; signed boundary lag and false-switch counts as diagnostics. A gain smaller than uncertainty does not establish general transfer.

Blind functional acceptance must independently enumerate all3^N paths on small synthetic inputs to verify the time-varying objective, exact ties and first-edge indexing; alpha=0 equivalence; H/A swap equivariance; forbidden states/+infinity, impossible frames, NaN/inf/shape rejection; empty/single rows, multiple runs/repeated period IDs, and independent periods. Include short H-A-H spells, same-team pass motion, abrupt actual turnover, stationary live control, dead restarts, ball disappearance without stoppage, teleports, full observation gaps, reacquisition and adversarial oscillating boundary scores. Fixtures and oracles must be independently designed, not copied from implementation helpers.

E2E promotion still requires a fresh exported package and minimal environment, actual local input->CSV inference, exact every-frame H/A/D/X contract, repeated deterministic hashes, official validator, measured wall time and actual process peak RSS plus safe failure without partial final files. Proposed efficiency bound: no more than20% inference regression and32MiB peak-RSS increase against the same-machine fresh accepted baseline, subject to root reviewing the overall competition budget **before runs**. These are recommended budgets, not measured results. Synthetic browser/package acceptance remains separate from private-data scientific scoring.

## Open risks and stop conditions

- Anonymous tracking cannot identify which player touched the ball. Margins can flip in a duel without team control changing; existing geometric features may not contain enough boundary signal.
- Long gaps are unidentifiable. A decoder may place a deterministic boundary by convention but must not claim recovered timing.
- Provider control labels differ from challenge possession-through-pass semantics. A better external boundary classifier can hurt challenge spell scoring; no challenge-label tuning is allowed.
- Ball slope smoothing blurs acceleration/direction changes. Touch detectors that work on clean high-quality tracking may fail on sparse tactical observations.
- False boundary support lowers the regularizer and can fragment spells. A head must earn its complexity on fresh data; revert to the accepted fallback if gates fail.
- Few independent matches and shared teams limit confidence. More corruption seeds do not create additional independent matches.
- Full PathCRF transfer remains unproven for anonymous slots, complete dead-play coverage, CPU resources and minimal packaging. HSMM's extra duration assumptions and archived GPL toolchain are unjustified unless measured errors warrant them.
